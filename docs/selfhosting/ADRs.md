# Self-Hosting Architectural Decision Records

Append-only. Historical entries are never edited; superseding decisions are new
entries. Date format: YYYY-MM-DD.

---

## ADR-SH-001 — Single translation unit via textual imports

**Date:** 2026-10-28
**Status:** Accepted

**Context.** The bootstrap compiler must compile its own source. CoreX has both
`import` (textual inclusion, flat namespace) and `module`/`mod` (separate units
with mangled symbols). Implementing modules in the bootstrap would add a
mangling pass, interface generation, and multi-unit driver logic before the
compiler can compile itself.

**Decision.** Structure the compiler as multiple files joined by `import` into
one translation unit rooted at `selfhost/corexc.cx`. No `module` declarations are
used by the bootstrap source.

**Alternatives.** (a) One large file — worse reviewability. (b) `module` units —
more bootstrap surface, no benefit for a single compiler binary.

**Consequences.** The compiler has one global namespace, so all top-level names
must stay unique. `import` resolution must be implemented by the bootstrap parser
(it is). The Rust compiler and the bootstrap compiler interpret imports
identically (textual inclusion).

## ADR-SH-002 — Bootstrap language subset, not a language change

**Date:** 2026-10-28
**Status:** Accepted

**Context.** The full CoreX v0.3 language includes `vec<T>`, slices, floats,
modules, function pointers, unions, bitfields, threads, TLS, inline asm, and C
`extern`. The compiler can be written without them.

**Decision.** Implement a documented bootstrap subset and write the compiler in
that subset. Unsupported constructs are rejected with a diagnostic. Do not add
language features or weaken semantics for the port.

**Alternatives.** Implement the full v0.3 surface before self-hosting — delays
the milestone and adds risk without changing the compiler's own requirements.

**Consequences.** The self-hosted compiler cannot compile all existing CoreX
examples (e.g. `features.cx` uses slices, `compiler_data.cx` uses `vec`). That is
recorded as a subset limitation, not a regression. The Rust compiler remains the
full-language reference.

## ADR-SH-003 — Process-lifetime arena allocation

**Date:** 2026-10-28
**Status:** Accepted

**Context.** The compiler allocates many small, long-lived objects (tokens, AST
nodes, types, symbols) and a few growable text buffers. Explicit free calls add
bookkeeping and failure modes.

**Decision.** Use one 512 MiB anonymous `mmap` arena, bump-allocated with 16-byte
alignment. Never free inside the compiler. Grow `Buf` by allocating a new block
and copying. Abort on arena exhaustion. Use fixed-size arrays only for small
local scratch buffers.

**Alternatives.** (a) `malloc`/`free` per node — slower, leak-prone, more code.
(b) Region arenas per phase — requires lifetime discipline without a memory win.

**Consequences.** No double-free/use-after-free inside the compiler; zero-filled
fresh pages; maximum RSS bounded by actual use; the process exit releases the
mapping. A pathological input larger than 512 MiB aborts rather than growing.

## ADR-SH-004 — Textual LLVM IR and external LLVM/cc tools

**Date:** 2026-10-28
**Status:** Accepted

**Context.** The existing Rust backend already emits textual LLVM IR and invokes
`llvm-as`, `opt`, `llc`, and `cc`. Reimplementing instruction selection or
linking would dwarf the port.

**Decision.** The self-hosted backend emits the same class of textual LLVM IR,
then invokes external tools with a fixed argv order. `--opt 0` is the bootstrap
default; `--opt 1..3` run `opt -passes=default<O{n}>` and `llc -O{n}`.

**Alternatives.** Link against LLVM libraries (new runtime dependency), emit
assembly/native code directly (far more work), or use Rust as a codegen service
(violates self-hosting).

**Consequences.** The compiler requires LLVM 20 tools and a C driver at build
time; the produced ELF is freestanding and does not require them at runtime.
Toolchain versions are pinned in `bootstrap.sh` and CI.

## ADR-SH-005 — First-class aggregate ABI in the self-hosted backend

**Date:** 2026-10-28
**Status:** Accepted

**Context.** CoreX passes `str` and structs by value. The Rust backend uses a
pointer/copy convention with hidden `sret` returns. Implementing that exact ABI
in the bootstrap backend is unnecessary: Stage 2/3/4 only need to interoperate
with code generated by the same backend.

**Decision.** Pass and return aggregates as first-class LLVM aggregate values
(`{ ptr, i64 }`, `%struct.X`). Consistently load/store aggregates for locals and
calls. Keep the Rust backend unchanged.

**Alternatives.** Replicate the Rust ABI exactly — more complex, no benefit for
self-hosting; use pointer-only aggregates — more code at every call/return.

**Consequences.** Stage 1 (Rust-compiled) and Stage 2 (self-compiled) have
different machine code/ABI but identical behavior on the corpus. Stage 2/3/4 are
byte-identical because they are compiled by the same backend. No cross-compiler
ABI compatibility is claimed.

## ADR-SH-006 — `else` blocks are explicit block statements

**Date:** 2026-10-28
**Status:** Accepted

**Context.** The first parser implementation stored `else { ... }` as the first
statement of the block. Codegen executed only that statement, silently dropping
the rest. This produced a compiler whose `else` branches were incomplete.

**Decision.** Wrap every `else { ... }` in an `S::Block` statement whose `body`
is the parsed statement list. `else if` remains an `If` statement.

**Alternatives.** Let semantic/codegen iterate a raw statement list for `els` —
inconsistent with every other block and easy to regress.

**Consequences.** All `else` bodies are checked and emitted. The bootstrap
regression corpus includes `if/else` bodies with multiple statements.

## ADR-SH-007 — Mask shift counts in emitted IR

**Date:** 2026-10-28
**Status:** Accepted

**Context.** CoreX defines `x << n` and `x >> n` with the count masked by
`bits-1`. LLVM shifts with a count ≥ bit width are poison and were optimized
away differently at `--opt 0` and `--opt 1..3`.

**Decision.** Emit `and <ty> count, bits-1` before every `shl`/`lshr`/`ashr`.
This matches the language definition and makes output opt-level invariant.

**Alternatives.** Force `llc -O0` and never run `opt` — hides the bug and
contradicts the spec; document UB — wrong.

**Consequences.** One extra IR instruction per shift; behavior is defined and
identical across optimization levels (validated by `arith` at `--opt 0..3`).

## ADR-SH-008 — Do not reuse `Expr.index` for field indices

**Date:** 2026-10-28
**Status:** Accepted

**Context.** Struct-literal checking stored the field index in the value
expression's `index` field. That field is also the builtin-id slot on `Call`
nodes, so `Outer { inner: make(3) }` made `make` look like builtin `print`, and
codegen crashed.

**Decision.** Struct literal codegen resolves fields by name via `find_field`;
do not write field indices into value expressions. `Expr.index` is reserved for
enum values and builtin call IDs.

**Alternatives.** Add a separate `field_index` field — unnecessary because the
field name is already present; use a distinct slot on all expressions — more
memory for a transient value.

**Consequences.** Nested calls/struct literals in field initializers work.
Regression covered by `tests/selfhosting/cases/positive/structs.cx`.

## ADR-SH-009 — Reproducibility means Stage 2 == Stage 3 (and 4)

**Date:** 2026-10-28
**Status:** Accepted

**Context.** Stage 1 is compiled by Rust and Stage 2 by the self-hosted backend;
their machine code/ABI differ by design. Comparing Stage 1 to Stage 2 would
produce a false reproducibility failure.

**Decision.** The reproducibility gate is `sha256(stage2) == sha256(stage3)` and
`sha256(stage3) == sha256(stage4)` under fixed `--opt 0`, LLVM 20.1.8, and cc
15.2.0. Equal hashes are required; a mismatch fails `bootstrap.sh`.

**Alternatives.** Normalized IR comparison only — weaker; allow differences with
a warning — would hide nondeterminism.

**Consequences.** Achieved: all three self-hosted stages hash to `2d66ed14…` at the time of this decision.
Stage 1 behavior is validated by the same corpus but not by hash equality.

## ADR-SH-010 — Rust Stage 0 remains the reference

**Date:** 2026-10-28
**Status:** Accepted

**Context.** The Rust compiler is complete, tested, and the oracle for expected
behavior. Rewriting or deleting it would remove the safety net.

**Decision.** Keep `compiler/` unchanged as Stage 0 and the full-language
reference. Add the self-hosted compiler under `selfhost/` with its own CLI
(`corexc`) and tests.

**Alternatives.** Replace Rust with the bootstrap compiler — loses the full
subset and the differential oracle; keep two compilers forever — acceptable
until the bootstrap subset reaches feature parity.

**Consequences.** `cargo test` remains the regression gate for the reference
compiler; `selfhost/bootstrap.sh` and `tests/selfhosting/` are the self-hosting
gates. No Rust source was modified for this milestone.

## ADR-SH-011 — Weak freestanding memory helpers for optimized builds

**Date:** 2026-10-28
**Status:** Accepted

**Context.** At `--opt 1..3`, LLVM's loop-idiom pass can rewrite byte loops into
calls to `memset`, `memcpy`, `memmove`, or `memcmp`. A freestanding link with
`-nostdlib` has no libc to provide them, so `stage2 build selfhost/corexc.cx
--opt 2` initially failed at link time.

**Decision.** Emit weak definitions of `memset`, `memcpy`, `memmove`, and
`memcmp` in every module, implemented with plain IR loops (the same approach as
the Rust backend). They are weak, so a user definition overrides them.

**Alternatives.** Force `-O0`/`opt` off — breaks `--opt` support; link libc —
violates the freestanding constraint; rely on `-fno-builtin` — does not stop
LLVM's loop-idiom pass.

**Consequences.** `--opt 1..3` self-compiles and links without libc. The final
fixed-point hashes are Stage 2/3/4 `11080572…`; Stage 1 is `0d75b20a…`.
The extra helpers increase the artifact size slightly.

## ADR-SH-012 — Slices: str-compatible layout, expected-type coercion, runtime range checks

**Date:** 2026-10-28
**Status:** Accepted

**Context.** After the Stage 3 fixed point the bootstrap subset still rejected
slices: the parser accepted `[T]` but semantic/codegen had no slice values,
range slicing was a parse error, and `&array` always produced `*[T; N]`. The
language spec (§3.1, §7.4) defines `[T]` as `{ ptr, i64 }` (identical to `str`),
with `&array`/`&mut array` producing a slice in a slice context and
`str`/array/slice ranges checked at runtime.

**Decision.**

1. Reuse the existing two-word layout: `llty`/`type_size`/`type_align` treat
   `K::Slice` exactly like `K::Str` (`{ ptr, i64 }`, 16 bytes, align 8).
   `str` stays a distinct `K::Str`; no implicit `str` ↔ `[u8]` coercion was
   added.
2. `&array`/`&mut array` yields `[T]` only when the expected type is a slice
   with the same element type (let initializer, argument, return, struct field,
   array literal element). Otherwise it remains a raw pointer.
3. Range slicing is a new `E::SliceRange` node. It reuses the operand slots —
   `lhs` = base, `rhs` = optional start, `args` = optional end — so `Expr` keeps
   its 152-byte layout (no new fields; consistent with ADR-SH-008).
4. Range codegen computes `start`, `end` (defaulting to 0/len), emits
   `start <= end && end <= len`, and aborts through `_cx_fatal` with
   `corex: slice range out of bounds` (exit 101) on violation, matching the
   Rust oracle. Literal `start > end` and literal bounds beyond a static array
   length are rejected in semantic analysis.
5. Element indexing (`a[i]`, `s[i]`) is unchanged and remains unchecked at
   runtime, as already documented for the subset. `data_ptr` on `[T]` returns
   `*T` (oracle parity); `print` accepts `[u8]` among slices.

**Alternatives.** Represent slices as a named struct — larger IR and additional
layout code for no benefit; add new `Expr` fields for the two bounds — grows
every AST node; bounds-check element indexing in the same change — a separate,
cross-cutting behavior change affecting existing corpus output.

**Consequences.** Slice coverage is proven by `tests/selfhosting/cases/positive/slices.cx`
plus three negative cases; the fixed point is re-established at Stage 2/3/4
`ff6677ca…`. Dynamic element-index checks remain the documented gap; slice
ranges are checked. `--opt 0..3` and the Rust Stage 0 suite are unaffected.

## ADR-SH-013 — Runtime element bounds checks and `str`/`[u8]` compatibility

**Date:** 2026-10-28
**Status:** Accepted

**Context.** After slice support landed, two documented gaps remained relative
to the spec and the Rust oracle: element indexing (`a[i]`, `s[i]`) was not
bounds-checked in generated code (§7.4 requires an abort with
`corex: index out of bounds`, exit 101), and `type_compat` had a dead
`str`/`[u8]` rule that never matched, so the §3.3 mutual compatibility of
`str` and `[u8]` did not work.

**Decision.**

1. Emit a single shared `gen_abort_if(cond, msg)` helper in `codegen.cx`. It
   branches to a block that calls `_cx_fatal` with the message on fd 2 and
   exits 101, then falls through. Both bounds checks use it.
2. Array indexing with a non-literal index emits
   `icmp ult i64 idx, len` against the compile-time length. Literal indices are
   validated in semantic analysis (`array index is out of bounds`) and skip the
   runtime check, matching the oracle's treatment of `ExprKind::Int`.
3. Slice and `str` indexing emit `extractvalue ..., 1` for the length and the
   same unsigned check. This also covers constant indices on slices, whose
   length is not known statically.
4. `type_compat` now accepts `str` where `[u8]` is expected and `[u8]` where
   `str` is expected. Both are `{ ptr, i64 }`, so no codegen conversion is
   needed; string literals still adopt `[u8; N]` only in that exact context.

**Alternatives.** Bounds-check only arrays and keep the range check — leaves
slice/`str` reads unsafe and diverges from the oracle; add a new abort path per
check — duplicates IR logic; keep indexing unchecked — contradicts spec §7.4
and the README's defined-behavior claim.

**Consequences.** Generated programs abort with the oracle's message and exit
code for out-of-range indexing in all corpus modes (`--opt 0..3`), and
`str`/`[u8]` values interoperate per spec. The fixed point moves to
Stage 2/3/4 `c417b392…` (Stage 1 `9d0cd417…`); the Rust Stage 0 suite remains
untouched at 205 passing tests. Verification cost grows by one compare/branch
and one string constant per dynamic index site.

## ADR-SH-014 — `vec<T>`: 24-byte header, context-inferred `vec_new`, spec growth

**Date:** 2026-10-28
**Status:** Accepted

**Context.** With slices complete, `vec<T>` was the next subset milestone
(FR-30). The Rust oracle defines a 24-byte header, `vec_new` element inference
from context, `vec_push` growth, `vec_free`, `vec_slice`, checked indexing, and
shallow copies. The bootstrap parser already reserved `vec` as a type token but
rejected it.

**Decision.**

1. `K::Vec` with one element type. Layout is `{ ptr, i64, i64 }`
   (`data`, `len`, `cap`), size 24, alignment 8, independent of the element
   type. `type_vec` is the only constructor.
2. `vec<T>` is parsed with a `vec_depth` counter and a `pending_gt` slot so
   `vec<vec<T>>` splits a lexed `>>` into two closing `>` tokens; triple and
   deeper nesting also works. `vec` remains a type-only keyword.
3. `vec_new(cap)` takes its element type from the expected type (let
   annotation, argument, return, field, array element). Without an expected
   `vec<T>` it is rejected (`cannot infer the element type`). The capacity must
   be `usize`.
4. Codegen uses the existing aggregate ABI: an entry-block alloca holds the
   header. `vec_new` allocates `cap * sizeof(T)` bytes when `cap != 0` and
   stores `null/0/cap` otherwise. `vec_push` grows to `max(4, cap * 2)` only
   when `len == cap`, copies `len * sizeof(T)` bytes with the module's weak
   `memcpy`, frees the old block with `_cx_free`, then stores the new element
   and increments `len`. `vec_free` frees `cap * sizeof(T)`, then writes
   `null/0/0`. `vec_slice` assembles a `{ ptr, i64 }` from fields 0 and 1;
   `len` loads field 1; indexing
   bounds-checks against field 1 and GEPs `data + idx`.
5. `vec` constants and globals are rejected: `vec_new` is a runtime call, and
   the subset has no data-section aggregate initializers. This is documented,
   not silently miscompiled.

**Alternatives.** Match the oracle's growth exactly (`cap == 0 ? 4 : cap * 2`)
— differs from the spec's `max(4, cap * 2)` for `cap == 1`, observable only in
unexposed capacity; the spec form was chosen. Pass vecs by pointer with an
`sret`-style ABI — unnecessary because Stage 2+ only interoperate with
themselves (ADR-SH-005). Infer `vec_new` from the argument — the argument is a
capacity, not an element.

**Consequences.** `vec<T>` works for scalar, struct, slice, `str`, and nested
`vec` elements; vecs are locals, parameters, returns, struct fields, and array
elements. The fixed point moves to Stage 2/3/4 `644c22c5…` (Stage 1 `7b2f8837…`).
Ownership stays manual and copies stay shallow, as specified.
