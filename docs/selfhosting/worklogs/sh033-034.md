## 2. SH-033 implementation

### 2.1 Volatile globals

- `parse_static` accepts `static mut volatile NAME: T = init;` after `mut`,
  matching the oracle's grammar, and stores `Decl.is_volatile`.
- Semantic analysis marks an identifier/path expression whose declaration is a
  volatile global (`Expr.is_volatile`). Codegen emits `load volatile` /
  `store volatile` for those places, including compound assignment
  (`FLAG += 1` loads and stores volatile).
- `volatile_load(ptr)` and `volatile_store(ptr, value)` lower to `load volatile`
  and `store volatile`; pointee types are checked (aggregate/void rejected) and
  the call requires `unsafe`.
- Aggregate volatile globals keep the oracle's behavior: the aggregate value is
  addressed, not loaded as one first-class value.

### 2.2 Atomic builtins

All twelve builtins from the spec are implemented:

`atomic_load`, `atomic_load_relaxed`, `atomic_store`,
`atomic_store_relaxed`, `atomic_fetch_add`, `atomic_fetch_sub`,
`atomic_fetch_and`, `atomic_fetch_or`, `atomic_fetch_xor`, `atomic_xchg`,
`atomic_cas`, `atomic_fence`.

- Semantics match `compiler/src/semantic.rs`: exact arity (1/2/3/0), pointer
  operand required, pointee may not be aggregate or void, value operands are
  checked against the pointee, and every call requires `unsafe`.
- Codegen matches the oracle's LLVM shapes: `load atomic`, `store atomic`,
  `atomicrmw`, `cmpxchg`, `fence seq_cst`; `_relaxed` uses `monotonic`;
  `atomic_cas` returns the `i1` success flag; fetch operations return the
  previous value.
- **Bool nuance:** the bootstrap represents `bool` as `i1`, while the oracle
  uses `i8`. LLVM rejects byte-unsized atomics, so bool atomics are lowered
  through `i8` (zext before store/cmpxchg/atomicrmw, trunc after load/fetch).
  Pointer atomics (`*mut T`) work directly. This was verified against the
  oracle for load, store, CAS, xchg, and pointer xchg
  (`tests/selfhosting/cases/positive/atomic_bool_ptr.cx`).

### 2.3 Inline assembly

- `asm(template)`, `asm(template, constraints)`, and
  `asm(template, constraints, operands...)` are supported.
- The template and constraints must be string literals; operands must be
  integers or pointers; the call requires `unsafe`; a constraint segment that
  starts with `=` after optional whitespace makes the result `usize`,
  otherwise `void`.
- Codegen emits `call [void|i64] asm sideeffect "<template>", "<constraints>"(ops)`.
  Templates are escaped as LLVM string constants (quotes, backslashes, control
  bytes as `\XX`), so multi-line templates and `$$` literal-dollar syntax work.
- Constraints are passed verbatim; there is no additional validator, matching
  the oracle and keeping LLVM's register allocator authoritative.

### 2.4 Threads and TLS

No language keywords were added. `std_thread` uses `clone(2)` in an inline-asm
trampoline and `std_tls` uses an explicit 64-slot table keyed by `gettid`.
Their syntax needs were function pointers, inline asm with five operands and
clobbers, atomics for the futex/spin locks, and `syscall`, all of which now
work. `let _ = <void>` is accepted (the oracle allows it) and codegen only
evaluates the expression.

## 3. Bugs found while closing the matrix

1. **Module include paths.** `mod name;` only searched the importing file's
   directory; `-I <lib/corex>` was ignored, so user programs could not import
   the standard library. `module_file` now searches the importing directory,
   then every `-I` directory, and accepts both `name.cx` and `name/mod.cx`,
   matching `compiler/src/driver.rs`.
2. **Local shadowing.** `lookup` checked module-mangled globals before locals,
   so `std_thread::spawn`'s parameter `stack_size` resolved to the module
   function `std_thread$stack_size`. Locals and parameters now shadow module
   items, matching the oracle.
3. **`let _ = <void>`.** The bootstrap rejected a void initializer even for the
   `_` binding, which broke `let _ = asm("pause", "")` in `std_sync`. It is now
   accepted and the expression is evaluated without an `alloca`.
4. **Inline-asm early clobber.** `std_thread`'s trampoline declared its output
   `={rax}` without `&`. `opt -O1` allocated an input operand to `%rax`, the
   trampoline overwrote it, and the thread segfaulted. The module now uses
   `=&{rax}`. This is a library fix, not a compiler workaround; the oracle
   build does not run `opt`, so only the bootstrap's `--opt 1..3` path exposed
   it.

## 7. Remaining limitations

- `volatile` qualifies globals and the two pointer builtins; there is no
  language-level `thread_local` and no thread join, matching the spec.
- Inline-asm constraints are passed through verbatim; an invalid constraint is
  diagnosed by `llvm-as`, not by the CoreX frontend (same as the oracle).
- Atomic pointees are restricted to non-aggregate, non-void types; float
  `atomic_fetch_*` uses the oracle's `atomicrmw` spelling and is not claimed to
  be useful.
- `lib/corex` has no unit-test harness; the matrix proves compilation, and
  `concurrency.sh` proves the runtime behaviour of the three concurrency
  modules.
- SH-039 (full Rust behavior suite), SH-037 (LSP/editor), SH-043 (remote CI),
  and SH-044 (cleanup) remain outside this workstream.
