## SH-029 — `for`, `do while`, labels, `goto`

Status: **COMPLETED**

### Semantics chosen (oracle is authoritative)

Read from `compiler/src/{parser,semantic,codegen}.rs`:

- `for (init; cond; step) body`: `init` is either `let …;`, an expression
  statement, or empty — **not** an assignment (the oracle's `parse_for` calls
  `parse_expr` then expects `;`). `step` is an expression, assignment, or
  compound assignment. Any clause may be empty; `for (;;)` is legal.
- `do body while cond;`.
- `name: stmt` is a label, recognised only when an identifier is followed by
  `:` at statement start. Labels are function-local, may appear anywhere in the
  function (including switch arms and after `return`/`goto`), and are collected
  in a pre-pass so forward `goto` resolves. Duplicates are rejected; `goto` to
  an unknown label is rejected.
- Return analysis (`stmt_diverges` in the oracle): `For`, `DoWhile`, and `Goto`
  do **not** diverge; `Label` diverges iff the labelled statement does. So
  `fn f() -> i32 { for (;;) {} }` is rejected by both compilers.
- Break ownership (`stmt_contains_break`): a `break` inside a nested `for`/`do
  while` does not count as a break of an enclosing loop; a label does not change
  break ownership.

### Implementation

- `selfhost/ast.cx`: `S` gains `For, DoWhile, Label, Goto`; `Stmt` gains
  `init`/`step` (`*mut Stmt`) for `for` clauses; new `Lbl { next, name, id }`
  node shared by semantic and codegen.
- `selfhost/parser.cx`: `parse_for`, `parse_do`, `parse_goto`, `parse_label`,
  and `parse_for_clause` (step clause). Label detection runs before the
  keyword dispatch. The old "not supported by the bootstrap compiler"
  rejection is gone.
- `selfhost/semantic.cx`: `Sem.labels`, `label_find`, `sdiag_name`,
  `collect_labels`/`collect_label_stmt` pre-pass per function; type checking for
  `for`/`do while` conditions (`bool` required); loop-depth handling so
  `break`/`continue` work inside both; `goto` target validation; `has_break`
  and `diverges` updated for `Label`.
- `selfhost/codegen.cx`: `Fn.labels`, `cg_collect_labels`/`cg_collect_label_stmt`
  assign one LLVM label id per distinct label before the body is emitted;
  `gen_for`, `gen_do_while`, and `Label`/`Goto` cases. `gen_block` now keeps
  scanning after a terminator, skipping dead non-label statements and emitting
  any label it finds (this is what makes `goto done; print(999); done:`
  resolve).
- `continue` in `for` targets the step block, `continue` in `do while` targets
  the condition block; `break` targets the loop end. Labels do not create a
  breakable scope, so `break` inside a label still binds to the enclosing loop.

### Evidence

Differential runs against the Rust oracle, `--opt 0..3`, byte-identical stdout
and exit status:

- `for_loops` (corpus): 10, 3, 4, 25, 3, 128, 8, 22, 1, rc 0.
- `goto_labels` (corpus): 3, 7, 42, 5, rc 0.
- Ad-hoc: switch arm containing `continue`/`break` inside a `for`, and a
  switch arm containing `continue` inside a `do while`.
- Return-analysis parity: `for (;;) {}`, `do {} while true;` rejected by both;
  `loop {}` and a `goto`-terminated body accepted by both.

Negative cases added (rejected by bootstrap and oracle): `undefined_label`,
`duplicate_label`, `cross_fn_label`, `for_condition`, `do_condition`.

### Limitations

- `goto` cannot jump into a block that the semantic pass did not reach; labels
  are collected syntactically, so any syntactic label is a legal target, which
  matches the oracle.
- The bootstrap emits an explicit `br` when falling into a label from an
  unterminated block; the oracle relies on LLVM's implicit fallthrough
  insertion. Both produce valid IR with identical behaviour.

## SH-027 — function types and function pointers

Status: **COMPLETED**

### Semantics chosen (oracle is authoritative)

- `fn(T1, T2) -> R` is a type; the return may be omitted (`fn()` means
  `fn() -> void`). `...` is accepted as the final parameter marker
  (`fn(i32, ...) -> i32`), matching the oracle's parser.
- Representation is a bare code pointer: `sizeof`/`alignof` are 8 on x86-64.
- `&f` where `f` is a declared function yields the function pointer; a function
  name used as a value (`let g: fn(i32)->i32 = inc;`) likewise decays to the
  pointer. `&local_variable` remains an ordinary address-of.
- Calls are indirect whenever the callee is not a direct reference to a
  declared function: a local binding shadows a function of the same name, and
  any non-identifier callee (`table[i](5)`, `(*p)(1)`, `o.f(2, 3)`) is
  indirect. An indirect call checks the argument list against the callee's
  `fn` signature.
- `null` is accepted where a function pointer is expected, and `==`/`!=`
  compare them. Ordering comparisons are rejected, as for pointers.
- `as` casts between function pointers, data pointers and integers follow the
  pointer rules (integer conversions still require `unsafe`).

### Implementation

- `selfhost/types.cx`: `K::Fn`; `Type` gains `next`, `params`, `ret`,
  `variadic`; `type_fn` constructor. `next` chains parameter types.
- `selfhost/parser.cx`: `fn (params) -> ret` in `parse_type`, including
  variadic and omitted return.
- `selfhost/semantic.cx`: `type_is_ptr_like` (`Ptr | CStr | Fn`) for `null`
  inference, pointer comparisons and casts; structural `type_eq` for `Fn`;
  size/align 8; `resolve_type` resolves parameter and return types (including
  through typedefs); `decl_fn_type`/`type_copy` build a signature from a
  declaration; `lookup_local` distinguishes shadowing locals;
  `check_indirect_call`; `&function` typing.
- `selfhost/codegen.cx`: `llty(Fn) = ptr`, pointer comparison and cast paths,
  `fn_ptr_val` (`@name`), `gen_indirect_call` (`call <ret> %p(args)`),
  `gen_call` dispatches on `expr.decl`.

### Evidence

Differential against the Rust oracle, `--opt 0..3`, byte-identical stdout/exit:

- `fn_pointers` (corpus): `42 42 -7 6 10 -5 1 2 11 20 -10`, rc 0 — covers
  `&inc`, bare `dbl`, a function-pointer parameter, a function-pointer return
  value, a `[fn(i32)->i32; 3]` dispatch table indexed at run time, and
  `null` comparison.
- `fn_ptr_layout` (corpus): `8 8 5 3 18 2 0 222`, rc 0 — covers `sizeof` /
  `alignof` of a function type, function pointers in struct fields and arrays
  of structs, a `fn()` (void, no parameters) pointer, and `!= null`.
- Negative cases rejected by both compilers: calling a non-function, a
  signature mismatch in a `let`, wrong arity through a pointer, a builtin used
  as a value, and a wrong-signature function stored in a struct field.
- A variadic function *type* parses and compares against `null` in both.

Known oracle bug (not reproduced): `let a: fn(i32)->i32 = &inc; let p:
*fn(i32)->i32 = &a;` makes the oracle emit `store ptr @a` and fail LLVM
verification. The bootstrap compiler emits the address of the local slot. This
workstream does not copy the bug and does not test that shape for parity.

### Limitations

- `Decl` has no variadic flag, so a function *pointer type* can be variadic but
  no declared function is. Variadic calls are SH-032.
- Function pointers in `static` initializers are not supported yet; that needs
  SH-023 (P0, unmerged). Dispatch tables as local arrays of function pointers
  work.
- Aggregate returns through a function pointer use the bootstrap's internal
  by-value ABI, which is what a bootstrap-compiled callee uses.
