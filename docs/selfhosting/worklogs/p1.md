## SH-029 — `for`, `do while`, labels, `goto`

Status: **COMPLETED**

### Semantics chosen (oracle is authoritative)

Read from `compiler/src/{parser,semantic,codegen}.rs`:

- `for (init; cond; step) body`: `init` is either `let …;`, an expression
  statement, or empty — **not** an assignment (the oracle's `parse_for` calls
  `parse_expr` then expects `;`). `step` is an expression, assignment, or
  compound assignment. Any clause may be empty; `for (;;)` is legal.
- `do body while cond;`.
- `name: stmt` is a label, recognised only when an identifier is followed by
  `:` at statement start. Labels are function-local, may appear anywhere in the
  function (including switch arms and after `return`/`goto`), and are collected
  in a pre-pass so forward `goto` resolves. Duplicates are rejected; `goto` to
  an unknown label is rejected.
- Return analysis (`stmt_diverges` in the oracle): `For`, `DoWhile`, and `Goto`
  do **not** diverge; `Label` diverges iff the labelled statement does. So
  `fn f() -> i32 { for (;;) {} }` is rejected by both compilers.
- Break ownership (`stmt_contains_break`): a `break` inside a nested `for`/`do
  while` does not count as a break of an enclosing loop; a label does not change
  break ownership.

### Implementation

- `selfhost/ast.cx`: `S` gains `For, DoWhile, Label, Goto`; `Stmt` gains
  `init`/`step` (`*mut Stmt`) for `for` clauses; new `Lbl { next, name, id }`
  node shared by semantic and codegen.
- `selfhost/parser.cx`: `parse_for`, `parse_do`, `parse_goto`, `parse_label`,
  and `parse_for_clause` (step clause). Label detection runs before the
  keyword dispatch. The old "not supported by the bootstrap compiler"
  rejection is gone.
- `selfhost/semantic.cx`: `Sem.labels`, `label_find`, `sdiag_name`,
  `collect_labels`/`collect_label_stmt` pre-pass per function; type checking for
  `for`/`do while` conditions (`bool` required); loop-depth handling so
  `break`/`continue` work inside both; `goto` target validation; `has_break`
  and `diverges` updated for `Label`.
- `selfhost/codegen.cx`: `Fn.labels`, `cg_collect_labels`/`cg_collect_label_stmt`
  assign one LLVM label id per distinct label before the body is emitted;
  `gen_for`, `gen_do_while`, and `Label`/`Goto` cases. `gen_block` now keeps
  scanning after a terminator, skipping dead non-label statements and emitting
  any label it finds (this is what makes `goto done; print(999); done:`
  resolve).
- `continue` in `for` targets the step block, `continue` in `do while` targets
  the condition block; `break` targets the loop end. Labels do not create a
  breakable scope, so `break` inside a label still binds to the enclosing loop.

### Evidence

Differential runs against the Rust oracle, `--opt 0..3`, byte-identical stdout
and exit status:

- `for_loops` (corpus): 10, 3, 4, 25, 3, 128, 8, 22, 1, rc 0.
- `goto_labels` (corpus): 3, 7, 42, 5, rc 0.
- Ad-hoc: switch arm containing `continue`/`break` inside a `for`, and a
  switch arm containing `continue` inside a `do while`.
- Return-analysis parity: `for (;;) {}`, `do {} while true;` rejected by both;
  `loop {}` and a `goto`-terminated body accepted by both.

Negative cases added (rejected by bootstrap and oracle): `undefined_label`,
`duplicate_label`, `cross_fn_label`, `for_condition`, `do_condition`.

## SH-027 — function types and function pointers

Status: **COMPLETED**

### Semantics chosen (oracle is authoritative)

- `fn(T1, T2) -> R` is a type; the return may be omitted (`fn()` means
  `fn() -> void`). `...` is accepted as the final parameter marker
  (`fn(i32, ...) -> i32`), matching the oracle's parser.
- Representation is a bare code pointer: `sizeof`/`alignof` are 8 on x86-64.
- `&f` where `f` is a declared function yields the function pointer; a function
  name used as a value (`let g: fn(i32)->i32 = inc;`) likewise decays to the
  pointer. `&local_variable` remains an ordinary address-of.
- Calls are indirect whenever the callee is not a direct reference to a
  declared function: a local binding shadows a function of the same name, and
  any non-identifier callee (`table[i](5)`, `(*p)(1)`, `o.f(2, 3)`) is
  indirect. An indirect call checks the argument list against the callee's
  `fn` signature.
- `null` is accepted where a function pointer is expected, and `==`/`!=`
  compare them. Ordering comparisons are rejected, as for pointers.
- `as` casts between function pointers, data pointers and integers follow the
  pointer rules (integer conversions still require `unsafe`).

### Implementation

- `selfhost/types.cx`: `K::Fn`; `Type` gains `next`, `params`, `ret`,
  `variadic`; `type_fn` constructor. `next` chains parameter types.
- `selfhost/parser.cx`: `fn (params) -> ret` in `parse_type`, including
  variadic and omitted return.
- `selfhost/semantic.cx`: `type_is_ptr_like` (`Ptr | CStr | Fn`) for `null`
  inference, pointer comparisons and casts; structural `type_eq` for `Fn`;
  size/align 8; `resolve_type` resolves parameter and return types (including
  through typedefs); `decl_fn_type`/`type_copy` build a signature from a
  declaration; `lookup_local` distinguishes shadowing locals;
  `check_indirect_call`; `&function` typing.
- `selfhost/codegen.cx`: `llty(Fn) = ptr`, pointer comparison and cast paths,
  `fn_ptr_val` (`@name`), `gen_indirect_call` (`call <ret> %p(args)`),
  `gen_call` dispatches on `expr.decl`.

### Evidence

Differential against the Rust oracle, `--opt 0..3`, byte-identical stdout/exit:

- `fn_pointers` (corpus): `42 42 -7 6 10 -5 1 2 11 20 -10`, rc 0 — covers
  `&inc`, bare `dbl`, a function-pointer parameter, a function-pointer return
  value, a `[fn(i32)->i32; 3]` dispatch table indexed at run time, and
  `null` comparison.
- `fn_ptr_layout` (corpus): `8 8 5 3 18 2 0 222`, rc 0 — covers `sizeof` /
  `alignof` of a function type, function pointers in struct fields and arrays
  of structs, a `fn()` (void, no parameters) pointer, and `!= null`.
- Negative cases rejected by both compilers: calling a non-function, a
  signature mismatch in a `let`, wrong arity through a pointer, a builtin used
  as a value, and a wrong-signature function stored in a struct field.
- A variadic function *type* parses and compares against `null` in both.

## SH-028 — unions, bitfields, flexible arrays, packed/`align(N)` structs

Status: **COMPLETED**

### Layout rules implemented (oracle is authoritative)

- `union U { ... }`: every field at offset 0; size is the largest field size
  rounded up to the largest field alignment (and any explicit alignment);
  alignment is the largest field alignment or the explicit alignment.
- `packed struct`: fields are not aligned between each other and the struct
  alignment stays 1 (unless `align(N)` is also given); size is the sum of the
  field sizes rounded to the alignment.
- `align(N) struct` (N a power of two): the struct alignment is
  `max(natural, N)` and the size is rounded up to it.
- `field: T: W`: bitfield. Consecutive bitfields of the same storage type share
  one storage unit while they fit; a new unit starts (aligned unless packed)
  otherwise. Reads shift and mask, and sign-extend when the field type is
  signed. Writes are a read-modify-write of the storage unit.
- `[T; 0]` as the last struct field is a flexible array member: it occupies no
  space. It is rejected anywhere but last, and inside unions.
- Rejected with diagnostics: bitfield width 0 or > 64 (parser), width greater
  than the type, non-integer bitfield type, duplicate field names, empty
  struct/union, `align` that is not a power of two, `offsetof` on a bitfield,
  and a type that contains itself by value.
- `sizeof`, `alignof` and `offsetof` report the computed layout for all of the
  above, and `offsetof` works on unions (always 0).

### Implementation

- `selfhost/ast.cx`: `Field.bit_width`/`bit_offset`;
  `Decl.is_union`/`is_packed`/`explicit_align`.
- `selfhost/parser.cx`: `parse_layout_attrs` (`repr(C)`, `packed`, `align(N)`)
  and `parse_struct_with_attrs`; `parse_struct` takes union/packed/align and
  parses `field: T: W`.
- `selfhost/semantic.cx`: `type_bits`, `field_duplicate`, rewritten
  `layout_struct` with union/packed/align/bitfield/flexible-array handling and
  the self-containment guard; `Expr.ival` carries the field byte offset; union
  literals must initialize exactly one field; `offsetof` rejects bitfields.
- `selfhost/codegen.cx`: `struct_plain`/`type_plain` decide the LLVM type.
  Plain structs keep `%struct.Name` and index GEPs. Any aggregate with a
  non-standard layout — and, transitively, any struct containing one — is
  lowered to `[size x i8]`; its fields are addressed with byte-offset GEPs and
  loaded/stored with explicit `align 1`, which is required because packed
  fields can be unaligned. Bitfield accesses go through
  `load_bitfield`/`store_bitfield`.
- `selfhost/codegen.cx`: plain structs still emit `%struct.*` type
  definitions; non-plain ones emit none.

### Evidence

Differential against the Rust oracle, `--opt 0..3`, byte-identical stdout/exit:

- `aggregate_layout` (corpus): `8 4 4 5 16 16 2 8 8 1 2 65 65 5 17 1 2 17 0 3`
  — `Point`/`Packed`/`Aligned`/`Bits`/`Flexible` sizes and alignments,
  `offsetof`, union field aliasing (`v.i` then `v.b`), bitfield read and write,
  and an `align(16)` literal.
- `aggregate_layout_packed` (corpus): `7 1 0 1 5 2 1 8 8 0 ...` — a packed

- Ad-hoc nested check: packed struct inside a struct, and an `align(8)` struct

## SH-030 — modules, interfaces, mangling, `corex.toml`, `#[cfg]`

Status: **COMPLETED** (with the interface limitation noted below)

### Semantics chosen (oracle is authoritative)

- A file may start with `module name;`. `mod name;` declares a dependency
  loaded from `<dir>/name.cx`, recursively; the file must begin with
  `module name;` or the build fails. Each module file is parsed as its own unit.
- Every top-level item of a module unit is emitted as `name$item`
  (`math$add`, `math$Vec2`, `math$Op`). The root unit's `main`/`_start` keep
  their unmangled names; a module's `main` is mangled like any other item.
- Unqualified references inside a unit resolve to the unit's own mangled names
  first (`Vec2` → `math$Vec2`), then to the flat namespace. Qualified
  references rewrite `a::b` → `a$b` in expressions, calls, types, struct
  literals, and `a::E::V` → enum `a$E` variant `V`.
- Only `pub` items are reachable from another unit; a private item is
  rejected with "item is private to its module" (functions, globals, constants,
  enum variants) or "type is private to its module" (structs, enums,
  typedefs). Fields have no per-field visibility, matching the oracle.
- `#[cfg(expr)]` before an item controls whether the item is emitted. Leaves
  are `key = "value"` (compared against `--cfg key=value`) or a bare `key`
  (compared against `--cfg key`), combined with `not(...)`, `all(...)`,
  `any(...)`. Disabled items are still parsed (no cascading syntax errors) but
  discarded.
- `corex.toml` is a small TOML subset. This workstream reads `sources = [...]`
  and `features = [...]` (each feature enables `feature=<name>`), and treats
  every listed source as a root unit of the whole-program build. Keys are
  matched at line start, so `name = "cfg_features"` cannot be mistaken for a
  `features` key.

### Implementation

- `selfhost/ast.cx`: `Program.module_name`/`deps`; `Decl.unit`/`is_pub`;
  `prog_append`.
- `selfhost/parser.cx`: `module`/`mod` items; `#[cfg]` parsing and evaluation
  with a per-parse cfg set; `add_item` applies the unit prefix, records
  `unit`/`is_pub`, exempts root entry points, and drops discarded items;
  qualified types (`a::T` → `a$T`) and 2/3-segment qualified paths including
  qualified struct literals; `parse_program_cfg(..., cfg, is_root)`.
- `selfhost/semantic.cx`: `Sem.cur_module`; module-aware `lookup` and
  `resolve_type`; `visible`; `decl_value_type`; qualified item/enum-variant
  resolution in `check_expr`, `eval_int` and `check_call`.
- `selfhost/codegen.cx`: qualified constants, globals and functions in value
  position (`E::Path` with a resolved decl).
- `selfhost/driver.cx`: recursive `mod` loading with a seen-set, module-name
  validation, `--cfg key=value` (repeatable), `corex.toml` detection (a path
  without a `.cx` suffix is a project directory), manifest source/feature
  extraction.

### Evidence

- `cases/modules/basic_math` (corpus, `--opt 0..3`): a `math` unit exporting a
  struct, enum, const and four functions, consumed by `app`; output
  `42 3 4 5 42 77` — byte-identical to the oracle.
- `cases/modules/cfg_features`: manifest `features = ["fast"]` selects
  `#[cfg(feature = "fast")]`; prints `100`.
- `cases/modules/private_access` (must fail): `math::secret()` from `app` is
  rejected.
- Ad-hoc: the same `main.cx`/`math.cx` project built by the oracle and the
  bootstrap compiler produces identical output; `emit-ir` shows `@math$add`,
  `@math$secret`, `@math$revealed`, `%struct.math$Vec2`, and an unmangled
  `@main`. `#[cfg]` matrix over `not`/`all`/bare keys verified.
- Manifest builds work at `--opt 0..3`, and with the oracle's

### Limitations

- **Interfaces are enforced, not emitted.** The oracle compiles each unit

- `pub` is accepted on functions, types, constants and globals but not
  enforced on `static` re-exports beyond the same visibility rule.
- A manifest source that is also a `mod` dependency is loaded twice and
  reported as a duplicate declaration; list only root sources in `sources`,
  as with the oracle's separate-compilation model.
- Legacy `import "file.cx";` inside a module unit would inline the imported
  file's items under the unit prefix. Mixing the two styles is not supported.

## SH-031 — expression macros and cfg attributes

Status: **COMPLETED**

### Semantics chosen (oracle is authoritative)

- `macro name(a, b) = <expr>;` declares a compile-time expression macro.
  `pub` is rejected on a macro.
- `name(args)` substitutes the argument expression *trees* into the body, so
  precedence is preserved: `square(p + 1)` expands to `(p+1) * (p+1)`, not
  `p + 1 * p + 1`.
- Expansion happens in the parser; expanded nodes are fresh copies, so a
  parameter used twice yields two independent trees. A macro name used as a
  value (`let x = m;`) is not expanded and is an undefined name, matching the
  oracle.
- Argument count is checked at expansion; a mismatch is a diagnostic. A macro
  cannot expand itself (its body is parsed before it is registered), so
  recursion surfaces as an undefined name, matching the oracle.
- `#[cfg]` attributes were delivered with SH-030 (gating whole items, with
  `not`/`all`/`any`/bare/keyed leaves and `--cfg`), which is the attribute half
  of this task.

### Implementation

- `selfhost/ast.cx`: `Macro { next, name, params, body }`.
- `selfhost/parser.cx`: macro item parsing, the `macros`/`macro_depth` parser
  state, `expr_clone`/`subst_expr`/`param_index`/`arg_at`, and expansion in the
  call postfix.

### Evidence

Differential against the oracle, byte-identical (and identical at
`--opt 0..3`):

- `cases/positive/macros.cx`: `25 6 18 25 7 10` — `square`, three-parameter
  `add3`, nested `twice(square(3))`, argument precedence with `square(p + 1)`,
  a field access inside a macro (`px(q)`), and a macro mixing calls.
- Negative cases rejected by both: `macro_arity` (wrong argument count) and

## SH-032 — C `extern`, variadics, hosted mode, C aggregate ABI, extra objects

Status: **COMPLETED**

### Semantics chosen (oracle is authoritative)

- `extern "C" fn name(params) -> R;` declares a C function. Its symbol is
  never module-mangled. Scalar and pointer parameters use the C ABI already.
- `extern "C" fn name(...) { body }` *defines* an exported C-ABI symbol; the
  body is compiled normally and the symbol keeps its name.
- `...` in a parameter list marks the declaration variadic. Extra arguments
  are checked loosely (scalars and pointers only, matching the C ABI) and
  passed with their own LLVM types.
- Aggregates pass by value using the LLVM aggregate type; the backend applies
  the System V classification, which matches C for the struct shapes tested
  (a 16-byte `{i64, i64}`). No sret marshalling is synthesised by hand.
- `--hosted` links against the system libc instead of `-nostdlib -static
  -no-pie`, and suppresses the custom `_start`/`__corex_entry` so the C runtime
  owns startup.
- `--shared` / `--emit shared` produces a shared object and also suppresses the
  entry; `--emit obj` emits a relocatable object (no entry, no link).
- `--link <obj|a>` adds inputs to the link, `-L <dir>` and `-l <name>` are
  forwarded to the linker driver.

### Implementation

- `selfhost/ast.cx`: `Decl.variadic`.
- `selfhost/parser.cx`: `...` in function parameter lists; extern declarations
  are exempt from module prefixing.
- `selfhost/semantic.cx`: `sem_run(..., require_entry)`; variadic calls accept
  extra scalar/pointer arguments and reject aggregate ones.
- `selfhost/codegen.cx`: `declare` is emitted only when a function has no body
  (so `extern "C" fn` with a body is defined); `, ...` in variadic
  declarations; extra call arguments; `cg_run(..., emit_entry)` skips the
  entry block on request.
- `selfhost/driver.cx`: `BuildOpts`, dynamic `cc` argument construction,

### Limitations

- The oracle's FFI test covers `f64` aggregates; floats are SH-019/SH-020 (P0,
  unmerged), so the bootstrap FFI corpus uses integer structs. The ABI path is
  the same.
- Aggregate interop relies on the LLVM backend's System V lowering of the
  aggregate type. Structs passed by value in the tested shapes work; exotic
  shapes (large aggregates, mixed float/int) are untested here and would need
  the float support first.
- Variadic *definitions* in CoreX are not supported (no `va_list`), matching the
  oracle: only C variadic callees are called.
- `--hosted` links a PIE and the linker warns about text relocations from the
  inline-assembly syscall stub; the binary is correct.

1. A function with an *empty* body (`fn f() { }`) was emitted as `declare`

   declarations of a builtin name are rejected as reserved, matching the
   oracle; module items are mangled and therefore unaffected.
