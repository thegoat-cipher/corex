### Divergences from the Rust CLI (documented, not regressions)

1. Diagnostic layout: bootstrap prints `path:line:col: error: msg`
   (or `error[E0201]`/`warning[W0001]`), without Rust's `--> file:l:c`, source
   snippet, or caret. Only `undefined …` maps to E0201; other frontend codes
   are not carried by the bootstrap parser/semantic diagnostics.
2. `emit-ir -o <path>` is still accepted (documented bootstrap extension);
   Rust rejects `-o` for `emit-ir`.
3. The REPL prints no `corex> ` prompts (input is fully buffered) and cannot
   run sessions that use language features absent from the bootstrap subset
   (`union`, function types). Rust's `repl_accepts_typedef_struct_union_and_function_pointer_items`
   therefore cannot pass yet; it is a P0/P1 language-surface dependency.
4. `build <directory|corex.toml>`, LSP, and line editing are out of scope here
   (SH-037).

### Crash fixes required by this work (found while exercising the CLI)

1. `check_expr` returned `null` for a null expression. `print(unsafe { … })`
   (a statement keyword where an expression is expected) then dereferenced the
   null type in `check_call` → SIGSEGV. Now returns a placeholder `i32` type;
   the already-recorded parse error is what the user sees.
2. `parse_struct_lit` and `parse_args` linked a null expression into a list and
   dereferenced it (`(*val).field = …`, `(*tail).next = …`) → SIGSEGV on
   malformed source. Both now stop with the existing diagnostic; array
   literals handle a null element too.

Both are malformed-input robustness issues (SH-040 evidence); they do not
change any valid program.

## SH-036 — link/emit flags (COMPLETED except `-g`)

### Flag matrix

| Flag | Behaviour | Evidence |
|---|---|---|
| `--emit obj` | Assemble + `llc` + copy the object to `-o`. Requires an entry point, like the Rust CLI. | `file entry.o` → "ELF 64-bit LSB relocatable"; no-entry → rc 1 |
| `--emit shared` | PIC object (`llc -relocation-model=pic`) linked with `cc -shared`; no entry point required | `file libadd.so` → "shared object"; `nm -D` exports `add`; `ctypes` calls it → 42 |
| `--emit staticlib` | PIC object archived with `llvm-ar rcs`; no entry point required | `llvm-ar t` lists one member; C driver links `libadd.a` → prints 42 |
| `--hosted` | No synthesized `_start`; links with `-no-pie` against the C runtime | `file hostmain` → dynamically linked; runs, rc 3 |
| `--shared` | Adds `-shared` to the link step (entry point still required) | `file hshared.so` → shared object |
| `--link <obj|a>` | Extra inputs passed to `cc` after the module object | C `twice` object linked; program rc 42 |
| `-L <dir>` / `-l <lib>` | `-L<dir>` / `-l<lib>` passed to `cc` | static `libtwice.a` linked through `-L/-l`; rc 42 |
| `-I <dir>` | Additional search directory for `import "name.cx"` when the importing file's directory has no such file (extension: Rust uses `-I` for `mod` discovery, which the bootstrap does not implement) | import found only with `-I` → rc 42; without → rc 1 |
| `--cfg name=value` | Accepted and recorded. It only gates `#[cfg(...)]`, and the bootstrap parser rejects attributes outright, so it has no observable effect. | build + run with `--cfg feature=fast` → rc 3 |
| `--sanitize` | Signed `+`, `-`, `*` on `i8/i16/i32/i64` use `llvm.{sadd,ssub,smul}.with.overflow` and trap with `corex: integer overflow` (exit 101). Bounds checks are always on. | overflow program → rc 101 + message at `--opt 0` and `--opt 2`; without the flag it wraps (rc 0) |
| `-g` / `--debug` | **Rejected**: `error: debug info (-g) is not supported by the bootstrap compiler`, rc 2 | CLI test |

`-g` is the one SH-036 flag not implemented: the bootstrap code generator emits
no `!dbg` metadata, so there is no line table or subprogram DWARF to produce.
Passing `-g` through to `llc` would silently do nothing, which is worse than a
diagnostic. Implementing it needs instruction-level debug locations in
`codegen.cx` (P1 language-surface work). `-g` therefore remains BLOCKED with a
concrete plan: attach `DILocation` metadata to emitted instructions, add
`DICompileUnit`/`DISubprogram` for each function, and emit `!llvm.dbg.cu`.

### Implementation notes

- `Cg` gained `sanitize`, `hosted`, `make_entry`; `cg_init` takes them and emits
  the overflow intrinsic declarations when sanitizing.
- `cg_run_ex(a,d,srcs,prog,sem,sanitize,hosted,make_entry)`; `cg_run` stays the
  default wrapper. `gen_entry` returns early for hosted / library output.
- `gen_simple_bin` routes signed `+ - *` through `gen_checked_arith`, which
  negates the overflow bit before `gen_abort_if` (that helper aborts when its
  condition is **false**).
- `dr_link` builds `cc` arguments dynamically (base flags, object, `--link`
  inputs, `-L`, `-l`); `dr_archive` prefers `llvm-ar`, falls back to `ar`.
- Parser state carries `-I` directories; `parse_program_opts` supplies them and
  `parse_program` keeps the old signature.

## SH-038 — differential token/AST/IR dumps (COMPLETED, divergences recorded)

### Dump modes

`corexc dump-tokens <file|->` prints `<kind> <line>:<col> <raw lexeme>` for
every token. `corexc dump-ast <file|->` prints, in source order:

```
item fn add
item struct Point
sig fn add(i32, i32) -> i32
...
count stmt.let 3
count expr.binary 7
...
```

The kind names and the 37 AST counters are generated from one table,
`tools/gen_dump_kinds.py`, which emits both the CoreX branches and the Rust
oracle's match, so the two schemas cannot drift.

### Oracle

`tests/selfhosting/dump_oracle.rs` links the Rust reference compiler library
(`compiler/target/release/libcorex.rlib`) and prints the same schema using
`corex::lexer::lex` / `corex::parser::parse`. `tests/selfhosting/dump.sh`
compiles it with `rustc --extern corex=…` (no new crate or dependency) and runs
all three comparisons over `tests/selfhosting/cases/positive`.

### Results

| Comparison | Result |
|---|---|
| tokens (kind, line:col, lexeme) | **exact match** on all 16 positive cases (and all `examples/*.cx` when checked manually) |
| AST (items, signatures, 37 counters) | **exact match** on all 16 positive cases |
| IR (normalized signatures) | match except the recorded ABI divergences below |

### Divergences found (recorded in `tests/selfhosting/dump-ir-expected.txt`)

1. **Aggregate parameter ABI.** Rust passes slices, `str`, and `vec` indirectly
   as `ptr` (`define i32 @sum(ptr %)`); the bootstrap passes the fat pointer /
   vector struct by value (`define i32 @sum({ ptr, i64 } %)`). Both are
   self-consistent, so freestanding programs behave identically, but the two
   compilers' objects are not link-compatible for aggregate parameters.
2. **Aggregate return ABI.** Rust returns structs through a hidden `sret`
   pointer (`define void @build(ptr %, i32 %)`); the bootstrap returns the
   struct value (`define { ptr, i64, i64 } @build(i32 %)`). LLVM lowers the
   latter to `sret` in machine code on SysV, so the machine ABI likely agrees,
   but the IR differs.
3. **Bool ABI.** Rust lowers `bool` to `i8`; the bootstrap lowers it to `i1`
   (`define i1 @eq(...)` vs `define i8 @eq(...)`).

Everything else in the normalized signature set matches exactly: user
functions, `main`, `_start`, and the weak `memcmp`/`memcpy`/`memmove`/`memset`
intrinsics.

Full IR text is deliberately not compared: label naming, temporary numbering,
bounds-check placement, and internal helper names (`_cx_*` vs `__corex_*`)
differ by design.

### Bug found and fixed

`dump-tokens` exposed that string tokens recorded the column **after** the
opening quote (the lexer consumed the quote, pushed the token, then adjusted the
byte offset but not the column). Fixed in `lx_lex_string`; token dumps now match
the oracle byte-for-byte.
