## SH-019/020/021 — floats (COMPLETED)

Scope: `f32`/`f64` types and literals, arithmetic `+ - * / %`, ordered
comparisons, integer<->float and f32<->f64 casts, parameters/returns, and
oracle-identical `print` formatting (six fractional digits, `nan`, `inf`,
`-inf`, abort 101 at `>= 1e18`).

### Design

- **Literal value model.** The lexer stores the binary64 bit pattern in the
  token (`Tok.ival`) and the parser copies it to `Expr.ival`; `f32` literals
  keep the binary64 pattern and the code generator narrows them. This mirrors
  the oracle (`TokenKind::Float(u64)`, `ExprKind::Float(f64)`).
- **Decimal -> binary64 without host floats.** `selfhost/runtime.cx` gains a
  fixed-capacity (192 x u32 limb) bignum and `rt_f64_bits`, which converts
  `D * 10^dexp` to a 54-bit quotient plus sticky remainder and applies
  round-to-nearest-even (normal, subnormal, overflow). Keeping this integer
  only means Stage 0 and every self-hosted stage agree bit-for-bit; using the
  compiler's own float support for its own parsing would be circular.
  Up to 1024 significant decimal digits are retained (far beyond the 17 that
  determine a binary64 value); longer literals are truncated with a sticky bit.
- **f32 narrowing.** `rt_f64_as_f32` rounds to binary32 (round-to-nearest-even,
  subnormal, overflow to infinity); `rt_f32_as_f64` widens back exactly.
  LLVM hex FP constants are always 64-bit patterns, so `float_ll` rounds f32
  literals to binary32 and widens before formatting, matching the oracle.
- **Types.** `FloatLit` adopts an expected `f32`/`f64`, otherwise `f64`.
  Arithmetic requires both operands to be the same float type and only
  `+ - * / %`; comparisons allow all six ordered predicates. No implicit
  int<->float conversion (`1.5 + 1` and `let x: f64 = 1;` are rejected).
- **Casts.** `int <-> float` and `float <-> float` are allowed without
  `unsafe`; `char`/enum <-> float stays rejected (matches the oracle's
  `Type::Int` vs `Type::Char`/`Type::Enum` split).
- **Codegen.** `fadd/fsub/fmul/fdiv/frem`, `fcmp oeq/une/olt/ole/ogt/oge`,
  `fneg`, `sitofp/uitofp/fptosi/fptoui`, `fpext/fptrunc`, and a
  `_cx_print_f64` helper that mirrors the oracle's `__corex_print_f64`
  instruction for instruction (`_cx_put_pad6`, `_cx_put_u64`, `_cx_newline`,
  `_cx_fatal`).
- **Constants.** `const F: f64 = <literal | -literal | f32 cast>` is folded in
  `eval_float_bits`; `cval_kind = 3` marks float constants. Non-literal float
  constant initializers are diagnosed rather than miscompiled.

### Known limitations

- Float constant initializers fold literals, unary minus, float-typed constant
  references, and float casts only (no float `const` arithmetic); rejected with
  a diagnostic.
- Literals longer than 1024 significant decimal digits are truncated with a
  sticky bit. This cannot change a binary64 result unless the exact value is
  within 10^-1024 relative of a rounding midpoint.
- `print` of a float follows the oracle's integer-part/6-digit algorithm,
  including its rounding of the fractional field (e.g. `999999.9999999` prints
  `999999.999999`).

## SH-022 — division/remainder runtime checks (COMPLETED)

`/`, `%` and their compound forms (`/=`, `%=`) now abort with exit 101 and
`corex: division by zero or signed overflow` on a zero divisor and on the
signed `MIN / -1` / `MIN % -1` overflow, before the `sdiv`/`udiv`/`srem`/
`urem` executes. Unsigned operators only test the zero divisor. Floating
division/remainder (`fdiv`/`frem`) are never guarded.

### Changed files

- `selfhost/codegen.cx` — `gen_guard_div` (zero test, signed `-1` and `MIN`
  tests, `and`/`or`, inverted into the "good" condition `gen_abort_if`
  expects); called from `gen_simple_bin` before the result temporary is
  allocated so the guard branch cannot split an instruction. The float path
  allocates its own temporary.
- `tests/selfhosting/cases/positive/{division,div_zero,rem_zero,div_overflow,rem_overflow,div_const_zero}.{cx,out,rc}`.
